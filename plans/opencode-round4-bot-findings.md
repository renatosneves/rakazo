## #1800 `fix/inbox-activity-polling`: foreground poll hook

Finding (P2 both bots): the `running` flag is reset whenever the effect restarts, so a quick background-and-back while a request is still pending starts a duplicate request.

Fix in `apps/mobile/lib/foreground-poll.ts`:
- Move the in-flight state to a `useRef` (`inFlight = useRef<Promise<unknown> | null>(null)`) that survives effect restarts.
- `tick()`:
  - if `inFlight.current` is set, wait for it, then schedule the next run from now. Don't start a second run.
  - otherwise set `inFlight.current = runRef.current()`, await it in `try/finally`, and clear it in `finally`.
- The effect cleanup still clears the timer, and doesn't touch `inFlight`.

Test in `lib/foreground-poll.test.tsx`: with a pending `run`, toggle foreground false then true. Expect `run` to have been called once, not twice. Then resolve it and expect the next call after `intervalMs`.
